# Plans and roadmap

## TL;DR

GitHub issues and milestones own live delivery state. Versioned execution plans explain multi-PR sequence and decisions. Active plans move to completed with outcome evidence; debt is recorded separately.

Use one issue and one milestone for each independently reviewable PR. FleetIQ milestone names are MNN - Outcome; the initial UI architecture and contract foundation belongs to M01 - Decisions and Contracts. Contract-backed semantic UI work belongs to M04 - Semantic Twin and Live UI. A plan may span milestones only when its slices name the milestone individually.

[The active UI foundation plan](exec-plans/active/ui-foundation.md) lists upcoming slices. [Completed plans](exec-plans/completed/README.md) retain results and supersession links. [Tech debt](exec-plans/tech-debt-tracker.md) records accepted gaps with an owner or review trigger. Use a lightweight issue for a single-PR task; use a plan for coordinated contract changes, migration, or multi-app rollout.
