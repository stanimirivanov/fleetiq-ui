# Product sense

## TL;DR

FleetIQ helps operators understand assets, their installed systems, live condition, and actionable changes across fleet types. A locomotive is one possible asset, not a hard-coded product model.

The operator should answer: what needs attention, which physical asset or component is affected, what evidence supports the status, and what can safely be done next? Preserve identity and context across tracker, vehicle, subsystem, and component. Favor explicit unknown or stale states over false precision. Keep safety-sensitive commands behind backend authorization and auditable confirmation.

The first web and mobile slices should use the same product language and backend contract while adapting interaction to each platform. Driver scoring, autonomous dispatch, voice command, 3D visualization, and industry-specific dashboards need separate product evidence and are not scaffold commitments. See [product specs](product-specs/index.md) for approved feature behavior.
