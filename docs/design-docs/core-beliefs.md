# Core beliefs

- The backend is authoritative; UI data is a validated projection.
- Domain vocabulary should describe assets and components without assuming a vehicle class.
- Web and mobile share contracts and pure behavior, not forced pixel parity.
- Keep a single owner for each kind of state and promote it only when a feature needs broader coordination.
- Explicit data freshness, provenance, and unknown states are more trustworthy than a polished but misleading dashboard.
- Prefer established libraries for transport, routing, forms, and architecture checks; prove new dependencies with delivered behavior.
- Document intent, then give maintainers fast executable feedback where the rule is structural.
