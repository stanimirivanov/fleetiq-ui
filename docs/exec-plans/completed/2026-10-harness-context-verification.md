# Self-validating harness context and verification

## TL;DR

Implement the first of three accepted harness PRs in M02. Make context discovery
reliable, qualify current sensors with permanent invalid fixtures, and bind
canonical local/CI verification to stable source bytes.

Status: completed
Milestone: M02 - Product Foundation

## Goal

Prevent ignored files, incomplete extraction, skipped gates or stale evidence
from creating misleading harness failures or acceptance passes.

## Scope

- Parsed Markdown, Git-owned discovery, visible routes and scoped budgets.
- Scoped app/feature/shared/browser/tool guidance and canonical verification docs.
- Actual-tool architecture/lint probes and an explicit compiler-API parser pin.
- Token, contract/provenance and generated-byte regression fixtures.
- Catalogue, structured evidence, CI-integrity policy and Windows qualification.
- Minimal shared registry type extraction required by newly checked type cycles.

## Design decisions

- Keep the current stack and individual commands; replace aggregate wiring.
- Use maintained Markdown/YAML parsers with exact development-only pins.
- Retain native TypeScript 7; pin the extraction parser only to its consumer.
- Fail qualification on missing tools, incomplete extraction or absent expected
  diagnostics. Preserve every existing boundary and the no-cycle policy.
- Record source hashes and bounded statuses without raw command output.
- Require owner review; distinguish external GitHub administration.

## Acceptance criteria

- Ignored IDE docs cannot fail; real invalid links, anchors, casing, routes,
  context size and plan metadata are rejected.
- Actual prohibited runtime/type-only imports and selected lint fixtures fail
  for expected diagnostics; valid public entries pass.
- Existing token, provenance/security and generated-byte requirements have
  positive/negative coverage.
- Canonical scripts and CI routes agree; missing/skippable gates fail.
- Incomplete/interrupted verification, or differing initial/final source
  snapshots, cannot pass.
- Canonical acceptance/browser groups and a disposable frozen install qualify
  the final slice without changing behavior or pinned contract bytes.
